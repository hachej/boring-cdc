# Unix owner request wire v1

Owner: `boring-cdc-tpma` (M1 CLI follow-up). Consumer: `boring-cdc-m2-fault-status.2`.

The operator socket is the only routine live-owner command transport. It is local Unix-domain only and is separate from the read-only status and metrics TCP listeners. Each message is a four-byte unsigned big-endian length followed by exactly that many UTF-8 JSON bytes. The length excludes the prefix, must be nonzero, and must not exceed `operator.max_request_bytes` for a request or `operator.max_response_bytes` for a response. The owner enforces `operator.read_timeout_ms` and `operator.write_timeout_ms` over each whole frame. It closes the connection after one response. An incomplete, extra, oversized, malformed, or version-mismatched frame has no state effect.

The owner obtains the caller's Linux peer credentials from the socket, requires the UID reported by `SO_PEERCRED` to match the connector account, and never accepts a claimed UID in JSON. The configured socket path remains below a connector-owned `0700` directory with a `0600` socket. It refuses a symlink, foreign owner, unsafe ancestor, or existing non-socket before binding. Error responses contain only a stable code and fixed redacted message. Raw driver, parser, filesystem, secret, nonce, and token values never enter logs or artifacts.

All JSON objects have `schema_version: 1`, a `kind`, and only the named fields. `invoke` carries `expected_run_id` and `argv`, the exact CLI argument vector without the binary name. The server uses the M1 registry parser. It accepts a live-owner or offline-eligible mutation only with `--dry-run`; a confirmed argv must use `apply`. The special read-only `destination verify` may use `invoke` because the owner persists its bounded audit result without a nonce. `run`, `run --bootstrap`, `init`, and maintenance operations cannot use this socket. The server checks the current run ID before issuing any plan or intent.

`argv` has at most 64 nonempty strings, each at most 4096 UTF-8 bytes. IDs and digests are nonempty, control-character-free strings of at most 256 bytes; `confirm_token` has at most 512 bytes. The peer UID is absent from every variant. Commands whose public grammar lacks `--dry-run` need an approved domain plan route before they can use this wire. This follow-up does not create that route.

`apply` carries `expected_run_id`, `request_id`, `canonical_payload_digest`, `plan_digest`, and `confirm_token`, all copied unchanged from the displayed plan. It never carries a new argv. The owner loads the persisted plan by request ID, checks the same peer identity and payload digest, and calls the plan's confirmation authorization against current action-relevant revisions, fingerprints, expiry, and predicates inside the sole writer transaction. It persists the accepted intent before any external effect and persists the terminal result before reply. A repeated identical `apply` returns that terminal result without dispatch. The same request ID with different payload, peer, token, or plan digest is a conflict. A prior-run nonterminal request is `aborted_by_restart` after external reconciliation and is never replayed automatically.

`result` carries `expected_run_id`, `request_id`, and `canonical_payload_digest`. It retrieves a persisted terminal result for the same peer; it never dispatches. If the request is still nonterminal, the response is a fixed `CLI_OPERATOR_RESULT_PENDING` error. A terminal result remains retrievable after plan expiry. A restarted run returns the persisted `aborted_by_restart` outcome when applicable.

The response is exactly one of `plan` containing the M1 `ActionPlan`, `result` containing the M1 `CliEnvelope`, or `error` containing `code` and `message`. The whole response is bounded before writing. `confirm_token` is present only in the direct plan response and is redacted by `redact_json` before logging or artifact storage. The CLI does not open SQLite writable while a live owner exists.

Stable request-boundary codes are `CLI_OPERATOR_FRAME_INVALID`, `CLI_OPERATOR_FRAME_TOO_LARGE`, `CLI_OPERATOR_WIRE_INVALID`, `CLI_OPERATOR_WIRE_VERSION`, `CLI_OPERATOR_COMMAND_NOT_ROUTABLE`, `CLI_OPERATOR_PEER_DENIED`, and `CLI_OPERATOR_RESULT_PENDING`. Domain failures retain their owning command codes. The M2 owner must implement the transport and sole-writer dispatch; this contract only freezes the wire and rejection boundary.

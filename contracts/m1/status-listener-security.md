# M1 status listener security material

Owner: `boring-cdc-m1-config.1`. This contract supplies the material interface consumed by `boring-cdc-m2-fault-status.2`.

The local default binds status and Prometheus to loopback with `authentication = false` and `tls = false`. A non-loopback bind requires both flags true. The flags must always agree. When true, `observability.status_tls_cert_env`, `status_tls_key_env`, and `status_tls_client_ca_env` are required, distinct uppercase environment-variable references. They hold a server PEM certificate chain, matching PEM private key, and PEM CA certificate bundle used to authenticate client certificates. Both TCP listeners use this same mTLS policy; neither has a mutation route. Anonymous clients and untrusted client certificates must be rejected before any status response. Plaintext public listeners are forbidden.

The three references are optional and inert when both flags are false. They are secret references, not material values. Their names and values must not appear in `PublicConfig` serialization, debug output, logs, status responses, or artifacts. `check` and `run` resolve them from the process environment into non-serializable, zeroized `SecretString` values. Missing, empty, oversized, or structurally malformed PEM material rejects configuration with a stable redacted code. The M2 listener must cryptographically parse the certificate, key, and trust roots, verify the key matches the certificate, and fail before binding on any error. `status` and offline read-only CLI commands validate the reference shape but do not resolve listener secrets.

Material is an immutable process-start snapshot. Operators rotate by updating the environment and restarting the sole runtime; no hot reload or in-place trust change is implied. Secret value rotation leaves compatibility fingerprints unchanged. A change to any reference name changes only the runtime fingerprint. The M2 endpoint must retain its parsed material only for the life of that process and must not emit TLS parser or handshake error strings that could include secret input.

The exact fields are inventoried as `SCN-M1-CONFIG-OBSERVABILITY-STATUS-TLS-CERT-ENV`, `SCN-M1-CONFIG-OBSERVABILITY-STATUS-TLS-KEY-ENV`, and `SCN-M1-CONFIG-OBSERVABILITY-STATUS-TLS-CLIENT-CA-ENV` in `config-cases.json`. CLI `status` literals are unchanged: it reads local durable state and does not contact or authenticate to the TCP listener.
